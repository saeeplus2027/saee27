# إصلاح بوابة تسجيل الدخول وإضافة المشاريع — سعي بلس

## ما الذي تغيّر؟

1. أصبح تصفح الموقع متاحًا دون حساب؛ لا تعترض بوابة الدخول النقرات العادية وروابط التنقل والاستفسارات والتقييمات.
2. تظل إضافة المشاريع والكتب والمنتجات والمحتوى الذي يحتاج حسابًا محمية بتسجيل الدخول.
3. إذا حاول الزائر إضافة مشروع قبل تسجيل الدخول، تحفظ الصفحة الإجراء المطلوب. بعد نجاح إنشاء الحساب أو تسجيل الدخول، تفتح نافذة إضافة المشروع تلقائيًا بدل مطالبة المستخدم بالعودة والضغط مرة أخرى.
4. تتحقق بوابة الحماية من جلسة الحساب الحالية أو رمز الجلسة المحفوظ، بدل الاعتماد على الرمز وحده.
5. في Worker: إذا كان البريد مسجلًا بالفعل وكلمة المرور التي أدخلها المستخدم صحيحة، ينشئ الخادم جلسة دخول ويرجع رمزها. وإذا كانت كلمة المرور مختلفة، يرجع خطأ واضحًا بدل نجاح غير مكتمل. وعند إنشاء حساب جديد، يُنشأ الحساب وجلسة الدخول معًا في عملية D1 batch.
6. تبقى إحصائيات إجمالي الحسابات والحسابات التي أضافت مشروعًا كما هي؛ الحساب يُحسب مرة واحدة ضمن الإجمالي ومرة واحدة فقط في عداد أصحاب المشاريع، حتى لو أضاف أكثر من مشروع.

## الملفات المعدّلة

- `public/index.html`
- `cloudflare/worker.js`

## النشر

1. استبدل `public/index.html` في GitHub بالملف الموجود في هذه الحزمة.
2. انشر `cloudflare/worker.js` إلى Worker الحالي `saee-plus-api`.
3. احتفظ بربط D1 الحالي `DB` وقاعدة البيانات `saee`، وربط R2 الحالي `Bucket`/`IMAGES` والحاوية `saee-media`. لا تنشئ قاعدة جديدة ولا تحذف بيانات.
4. انتظر نجاح GitHub Pages، ثم نفّذ تحديثًا قويًا للمتصفح `Ctrl + Shift + R`.

## ملاحظات

- لا تتضمن هذه الحزمة تغييرًا على قاعدة البيانات أو حذفًا للحسابات.
- إذا كان البريد مستخدمًا من قبل، يجب أن تكون كلمة المرور المدخلة هي كلمة مرور ذلك الحساب. لا يمكن إعادة إنشاء حساب بعنوان بريد مستخدم بكلمة مرور مختلفة؛ استخدم تسجيل الدخول أو استعادة كلمة المرور.
- تم فحص صياغة JavaScript للسكريبتات المضمنة وWorker باستخدام Node.js. لم يتم النشر إلى حساب Cloudflare أو GitHub من هنا.
