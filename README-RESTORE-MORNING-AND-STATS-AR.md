# استعادة نسخة سعي بلس مع إحصائيات الحسابات والمشاريع

هذه الحزمة مبنية على نسخة المشروع المرفوعة صباح 21 نوفمبر 2026، مع إبقاء صفحات **فرص سعي** و**تقييم الموقع** و**المساعد سعي** وميزات الإدارة الموجودة فيها.

## ما الذي تم إرجاعه أو إضافته؟

- التسجيل موحّد: لا يوجد اختيار بين مستخدم عادي وصاحب مشروع. كل حساب جديد نوعه واحد.
- إنشاء الحساب ينشئ الحساب وجلسة الدخول في عملية D1 واحدة، ويرجع رمز الجلسة للموقع ليتم تسجيل الدخول مباشرة.
- إذا كان البريد مسجّلًا بالفعل وأُعيدت محاولة إنشاء الحساب بكلمة المرور الصحيحة، ينشئ الخادم جلسة دخول جديدة بدل إرجاع نجاح غير مكتمل. وإذا كانت كلمة المرور مختلفة تظهر رسالة واضحة.
- يستطيع أي حساب مسجّل إضافة مشروع، رفع صورة أو إضافة رابط، اختيار أماكن النشر، انتظار موافقة الإدارة، ثم تعديل مشاريعه من قسم «مشاريعي».
- تستمر صفحة «فرص سعي» ورابط منصة نحن وتفاصيل الفرص التي يديرها الأدمن. وتظهر فيها كذلك المشاريع التي وافقت عليها الإدارة عند اختيار نشرها ضمن فرص سعي.
- تمت إضافة API لتقييم الموقع حتى يتم حفظ تقييمات الزوار وإظهارها في لوحة الإدارة.
- الإحصائيات تعرض: إجمالي حسابات المستخدمين، وعدد الحسابات التي أضافت مشروعًا واحدًا على الأقل. الحساب يُحسب مرة واحدة فقط مهما أضاف مشاريع متعددة؛ وعدد أصحاب المشاريع جزء من الإجمالي. تشمل المشاركة المشاريع المرسلة بانتظار الموافقة أو المنشورة أو المرفوضة.

## الملفات الرئيسية التي تغيرت

- `public/index.html` و`index.html`: واجهة الحساب الموحد، الدخول الفوري بعد التسجيل، زر «مشاريعي»، والروابط واستعادة صفحات الصباح.
- `public/app.js`: عرض فرص سعي وتقييم الموقع، إضافة المشاريع وإدارتها، وإحصائيات الحسابات.
- `public/admin.js`: إدارة فرص سعي والتقييمات ومراجعة مشاريع المستخدمين.
- `cloudflare/worker.js`: التسجيل والجلسات والمشاريع والمراجعة والإحصائيات وAPI التقييمات.
- `cloudflare/schema.sql` و`cloudflare/migrations/0004_unified_accounts_community_projects.sql`: جداول المشاريع المطلوبة دون فرض عمود نوع الحساب.
- `.github/workflows/nextjs.yml`: إضافة مهلة قصيرة بعد رفع GitHub Pages artifact قبل محاولة النشر لتقليل احتمال خطأ ظهور بيانات الـ artifact مباشرة بعد الرفع.

## خطوات النشر

1. ارفع محتويات مجلد `public` إلى مجلد `public` في مستودع GitHub، ويفضل أن تكون كلها في Commit واحد حتى لا تبدأ عمليات نشر متزامنة لكل ملف.
2. استبدل `cloudflare/worker.js` في Worker الحالي `saee-plus-api` ثم اضغط Deploy.
3. احتفظ بربط D1 الحالي: `DB` إلى قاعدة `saee`. لا تنشئ قاعدة جديدة ولا تحذف قاعدة البيانات.
4. احتفظ بربط R2 الحالي. الكود يقبل أسماء الربط `IMAGES` أو `BUCKET` أو `Bucket`، وبالتالي يدعم ربطك الحالي.
5. لا حاجة لإضافة نوع حساب أو ترحيل عمود `account_type`. إذا كان هذا العمود موجودًا من نشر سابق، يترك كما هو ويُتجاهل.
6. بعد نجاح GitHub Pages وWorker، افتح الموقع مع تحديث قوي `Ctrl+Shift+R`.

`cloudflare/worker.js` ينشئ جدول `community_projects` تلقائيًا عند أول طلب API. ملف migration مرفق كخيار بديل فقط؛ لا تشغّل ملف schema كاملًا على قاعدة بيانات الإنتاج من دون مراجعة مسبقة.

## اختبار سريع

- افتح `https://saee-plus-api.ligagym.workers.dev/api/me`؛ من دون جلسة يجب أن يرجع `{"user":null}`.
- أنشئ حسابًا جديدًا: يجب أن تُغلق نافذة التسجيل ويظهر اسم الحساب مباشرة.
- أرسل مشروعًا: يجب أن يظهر في لوحة الإدارة للمراجعة، ثم يظهر في الواجهة بعد الموافقة.
- افتح «الإحصائيات»: يظهر العدد الإجمالي وعدد الحسابات التي أضافت مشروعًا.
- أرسل تقييمًا من صفحة «تقييم الموقع»، ثم راجعه من لوحة الإدارة.

لم يتم نشر هذه الحزمة تلقائيًا إلى GitHub أو Cloudflare؛ يجب تطبيقها على المستودع والـ Worker الحاليين.
